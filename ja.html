なぜ人間の勘によるインデックス設計は破綻するのか？

01. インデックス爆発の防止

人間は遅いクエリごとに勘で複合インデックスを貼り散らかし、INSERT/UPDATEを激重にしメモリを浪費します。pg_solverは最小限のインデックス集合だけを特定します。

02. 幾何学大域最適化 (POCS)

ワークロード全体を多次元凸制約空間に射影。局所解にハマるヒューリスティックを回避し、ミリ秒でシステム全体にとっての最適解を算出します。

03. 完全エアギャップ ＆ 無停止

外部SaaSと異なり、クエリ内容や社内データは一切外部送信されません（通信ゼロ）。インデックス作成は CONCURRENTLY で本番ロックを発生させません。

わずか3分で導入完了。DB停止ゼロ。

標準PostgreSQL Extensionプロトコル準拠。ファイルを置いてコマンドを叩くだけ。

1

共有ライブラリ（.so）を配置

PostgreSQLのライブラリおよび拡張ディレクトリにファイルをコピーします：

sudo cp pg_solver.so $(pg_config --pkglibdir)/
sudo cp pg_solver.control pg_solver--0.1.0.sql $(pg_config --sharedir)/extension/
2

拡張を有効化 ＆ 診断レポート確認

DBに手を加える前に、まずは現状のボトルネックと改善予測レポートを出力します：

CREATE EXTENSION pg_solver;
SELECT pg_solver_report();
3

ワンタッチで最適化を適用

CONCURRENTLY で無停止適用。いつでも `pg_solver_revert()` で安全に元に戻せます：

SELECT pg_solver_apply();
